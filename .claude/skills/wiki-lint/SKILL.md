# Wiki Lint — LLM Wiki 구조 점검

이 위키는 사람이 아니라 LLM이 유지보수하는 지식 베이스다. 깨진 링크나 색인 누락은
사람 눈에는 사소해 보여도 "index.md로 페이지를 찾고 [[링크]]로 그래프를 탐색하는"
LLM 워크플로우를 직접 망가뜨린다. 그래서 점검은 감으로 하지 않고 스크립트로 한다.

## 점검 실행

위키 루트(wiki/와 index.md가 있는 곳)에서:

```bash
python .claude/skills/wiki-lint/scripts/wiki_lint.py
```

- 다른 위치의 위키: `--root <경로>`
- 프로그램 처리용: `--json` (errors/warnings/infos 배열 + ok 불리언)
- 종료 코드: ERROR가 있으면 1, 깨끗하면 0
- Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8` 환경변수를 설정

스크립트가 검사하는 규칙의 원전은 위키 루트의 `SCHEMA.md`다. 점검 결과가
SCHEMA.md와 모순되어 보이면 SCHEMA.md가 우선이며, 스크립트를 고쳐야 한다.

## 결과 해석과 수정 가이드

| 항목 | 의미 | 수정 방법 |
|------|------|----------|
| 깨진 링크 | 존재하지 않는 페이지를 [[참조]] | 페이지를 만들거나, 외부 링크로 바꾸거나, 링크 제거. MOC의 "아직 없는 주제"는 [[링크]] 대신 일반 텍스트로 |
| index.md 누락 | 색인에 없어 LLM이 페이지를 못 찾음 | index.md 해당 도메인 섹션에 `[[slug]] — 한 줄 요약` 추가 |
| MOC 미등재 | 도메인 지도에 페이지가 빠짐 | 해당 `{도메인}-moc.md`의 적절한 섹션에 숙련도와 함께 추가 |
| frontmatter 오류 | 필드 누락/잘못된 값 | SCHEMA.md 형식으로 보정. concept/entity는 maturity 필수, moc/event는 생략 |
| 첫 태그 불일치 | tags[0]은 도메인명이어야 함 | 첫 태그를 dev/cs/ai/geopolitics/military/concepts 중 하나로 |
| 고아 페이지 (WARN) | 아무 페이지도 링크하지 않음 | 관련 페이지 본문에서 [[링크]] 연결 (MOC 등재만으로는 부족하지 않음 — MOC도 페이지다) |
| 오래된 페이지 (INFO) | updated 6개월 초과 | 내용이 여전히 유효한지 확인 후 갱신하거나 그대로 둠 — 자동 수정 금지 |

## 점검 후 행동 원칙

1. **리포트 먼저, 수정은 승인 후.** 이 위키의 운영 원칙(CLAUDE.md)상 사용자 승인
   없이 파일을 쓰지 않는다. 점검 결과를 분류해서 보여주고, 수정 제안을 명확히
   설명한 뒤 승인을 받아 고친다.
2. **ERROR부터.** WARN/INFO는 판단의 여지가 있지만 ERROR는 구조 규칙 위반이다.
3. **수정 후 재실행.** 고친 다음 스크립트를 다시 돌려 ERROR 0을 확인하고,
   `log.md`에 `## [YYYY-MM-DD] lint | {수정 요약}` 항목을 추가한다.
4. **maturity 분포(INFO)는 지식 맵 신호다.** seed가 쌓인 도메인은 소화가 밀린
   것이고, 페이지가 MOC뿐인 도메인은 빈 지식 영역이다. 사용자에게 학습 우선순위
   관점에서 한 줄 코멘트를 곁들이면 좋다.

## 스크립트가 못 잡는 것

내용 차원의 문제는 직접 읽어야 한다. 사용자가 "전체 점검"을 원하면 스크립트 실행에
더해 다음을 수동 확인한다:

- **모순**: 서로 다른 페이지의 상충 정보 (전체 페이지를 읽고 교차 비교)
- **주제 중복**: 같은 주제를 다루는 두 페이지 (병합 제안)
- **잘못된 분류**: 내용과 도메인 폴더가 안 맞는 경우
